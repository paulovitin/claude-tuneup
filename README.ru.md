# claude-tuneup

### Правила, которые вы написали для Claude, стоят вам дороже, чем коробка со старым хламом.

AI-агент проводит аудит инструкций, загружаемых в **каждую сессию** — и очищает диск.<br/>
Каждое изменение — это кнопка. У каждой кнопки есть пояснение *"Что это делает?"*. Любой запуск можно отменить.

> [!IMPORTANT]
> **Знаете ли вы?** Anthropic сократила системный промпт самого Claude Code более чем на **80%** для моделей поколения Claude 5. Устаревшие правила в `CLAUDE.md` или `SOUL.md` расходуют токены в каждой сессии. `claude-tuneup` проводит аудит контекста по официальным гайдам Anthropic!

Месяцы работы с Claude Code оставляют след на диске. Но более дорогой след — в ваших
инструкциях: правила, написанные, чтобы компенсировать старые модели; одна и та же установка,
скопированная в четыре файла; описания навыков, которые плохо маршрутизируют; `SOUL.md`, за
который вы платите в каждой сессии, релевантен он или нет. Всё это загружается прежде, чем вы
напечатаете хоть слово.

У вас есть возражения против инструмента, который хочет всё это трогать. **Отлично.** Этот
инструмент сделан именно для таких, как вы, — так что выслушаем их, одно за другим. Уже
убеждены? Команда установки [вот здесь](#-ладно-что-мне-набрать). Не убеждены? Ещё лучше.
Читайте дальше.

## 🧐 «Вы хотите переписывать правила, которые написал *Я*?»

**Нет — он хочет *предлагать*, а ручка только у вас.** Группа `instructions` (шаги 12–18)
никогда не редактирует правило сама. Она показывает исходную строку, предлагаемую замену и
причину — и ничего не меняет, пока вы не нажмёте кнопку:

```text
> claude-tuneup

📝 ШАГ 12: Правила, которые должны быть суждением

   ~/.claude/CLAUDE.md:14
   "по умолчанию не пиши комментарии. Никогда не пиши docstring на несколько абзацев."

   Написано для старой модели. Современные модели читают окружающий код.
   Предложение: "Пиши код, который читается как окружающий: следуй его
                плотности комментариев, именованию и идиомам."

   [ Переписать ]   [ Оставить как есть ]   [ Удалить ]   [ Что это делает? ]
```

Три вещи, которых этот транскрипт не покажет:

- **Абсолюты безопасности неприкосновенны.** Правила вроде «никогда не пушить в main» или
  «никогда не коммитить секреты» сохраняются **дословно** — никогда не смягчаются и не
  «улучшаются».
- **Оставить помеченное правило — всегда допустимый ответ.** Инструмент помечает; судите вы.
- **Вам никогда не придётся судить о том, чего вы не можете опознать.** У каждого вопроса есть
  опция *«Что это делает?»*, которая изучает и объясняет элемент **до** вашего решения.

## 📐 «Переписывать на основании *чего* — вашего вкуса?»

**Ноль мнений.** Каждая проверка группы `instructions` реализует одно правило из статьи
Anthropic
[**The new rules of context engineering for Claude 5 generation models**](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models):

| Правило | Проверка |
| --- | --- |
| Предпочитайте суждение жёстким правилам | **шаг 12** — переписывает правила, написанные для компенсации старых моделей, сохраняя абсолюты безопасности дословно |
| Не воюйте с harness | **шаг 13** — помечает инструкции, противоречащие тому, что рантайм уже делает |
| Скажите один раз | **шаг 14** — одна и та же инструкция в `CLAUDE.md`, телах агентов, описаниях агентов и навыков |
| Интерфейсы вместо примеров | **шаг 15** — поля `description`, маршрутизирующие по возможностям, а не по примерам формулировок |
| Прогрессивное раскрытие | **шаг 16** — что остаётся всегда загруженным, а что становится лениво загружаемым навыком |
| Пусть автопамять занимается памятью | **шаг 10** — `SOUL.md` уходит на покой в собственную память Claude Code |

Он задаёт другой вопрос, чем «что можно удалить?» — он спрашивает **«это всё ещё помогает?»**.
И навык предъявляет те же требования к себе: в контекст попадает только плейбук той группы,
которую вы запускаете, — та же дисциплина токенов, которую он требует от вашего `CLAUDE.md`.

## 🩺 «В Claude Code уже есть `/doctor`. Зачем существуете вы?»

**Потому что `/doctor` идёт первым — этот инструмент на этом настаивает.** `/doctor` лучше
проводит инвентаризацию: он видит реальное использование по компонентам во всех проектах и
стоимость резидентных токенов — то, что не измерит ни один внешний навык. Поэтому claude-tuneup
запускает его за вас и работает по его отчёту, тратя собственные усилия на то, чего `/doctor`
не касается: ваш **глобальный** `CLAUDE.md`, описания агентов и навыков, устаревший `SOUL.md` и
диск. Дополнение, а не замена.

> **«А когда навык запускает `/doctor` без интерфейса — что мешает *ему* что-то менять?»**
> Вызов всегда несёт инструкцию «только отчёт», и тест проверяет её наличие в каждой команде,
> которую строит навык, — у headless-запуска нет диалогов подтверждения, поэтому инструкция —
> это предохранитель, а тест — предохранитель предохранителя.

⏱️ Честный бюджет: полный запуск ждёт около **6 минут** на проходе `/doctor` в начале и
спрашивает разрешения, прежде чем потратить ещё 6 на проверку результата.

## 🗂️ «Он тронет мою историю чатов?»

**Только если вы попросите, подтвердите по каждой папке и примете предупреждение — и никогда
оптом.** Транскрипты разговоров и состояние сессий (`projects/`, `todos/`, `shell-snapshots/`,
`file-history/`, `history.jsonl`) — наименее восстановимые данные на машине, и они **никогда**
не удаляются массово. По умолчанию — *сохранить*. Максимум — предлагается чистка по возрасту
(«транскрипты старше 6 месяцев: 142 сессии, 1.2G») с явным подтверждением по каждой папке и
предупреждением, что это необратимо и ломает `--resume` и `/insights`.

## ↩️ «А в день, когда я пожалею о клике?»

```bash
claude-tuneup restore    # выберите точку восстановления → полностью, только конфиги или только элементы
```

**Каждый запуск — точка восстановления.** Конфиги снимаются в снапшот, а удалённые элементы
*перемещаются* — никогда не `rm` — в `~/.claude-tuneup/backups/<run-id>/`, хранящийся **вне**
каталога навыка, чтобы обновление или переустановка не стёрли историю отмен (переопределяется
через `$CLAUDE_TUNEUP_STATE`). Снапшоты доступны только владельцу, потому что `.claude.json`
может содержать токены.

Запуск не только вычитает, но и *добавляет*, и откат теперь отменяет и то и другое: навыки,
написанные для вас во время запуска, фиксируются и убираются при полном восстановлении —
*перемещаются* в `undone-creations/`, а не удаляются: вы могли их с тех пор отредактировать.

> **«А само восстановление может что-то сломать?»**
> Оно тоже параноидально. Перед откатом оно снимает ваши *текущие* конфиги в папку
> `pre-restore-…` — так что даже отмена отменяема — и никогда не перезаписывает более новый
> элемент, занявший освободившийся путь: коллизии ложатся в `<путь>.restored-<ts>` и
> отражаются в отчёте.

## 🧯 «О чём я не догадался спросить?»

Режимы отказа, о которых он уже позаботился, чтобы вам не пришлось:

- **Смена формата файла не обманет его на массовое удаление.** Если `installed_plugins.json`
  однажды распарсится пустым, пока на диске есть содержимое плагинов, навык откажется считать
  «не в списке» равным «не установлен».
- **Он не продаёт бессмысленную экономию места.** Самовосстанавливающиеся артефакты (venv, кэши,
  рантаймы, `statsig`) распознаются — он укажет настоящее решение (отключить владеющий плагин)
  вместо удаления того, что пересоберётся через неделю.
- **Он изучает, а не предполагает.** Элементы классифицируются по признакам — размер, возраст,
  битые ссылки, тип транспорта — а не по зашитым именам.
- **Ваши данные `/insights` остаются вашими.** Они читаются вживую для подсказок и никогда не
  копируются в навык или куда-либо ещё. Встроенные учётные данные в конфигах MCP помечаются
  только по **имени** переменной окружения; значения никогда не печатаются.

## 🤝 «Я стандартизировался на `AGENTS.md`. Это будет воевать с моей настройкой?»

**Наоборот — он предлагает чистый мост.** Claude Code не загружает `AGENTS.md` автоматически,
поэтому репозитории на кросс-инструментальной конвенции (Codex, Cursor, Gemini CLI…) обычно
обзаводятся копией в `CLAUDE.md`, которая **тихо расходится**. Tune-up обнаруживает этот дрейф и
консолидирует: общая правда живёт один раз в `AGENTS.md`, а `CLAUDE.md` становится шимом на три
строки —

```markdown
@AGENTS.md

# Только для Claude
- (дельты, которые должен видеть только Claude Code)
```

Один вопрос по согласию; пользователи только Claude его никогда не увидят. Импорты здесь лучше
симлинков: симлинк делает `CLAUDE.md` *тем же самым* `AGENTS.md`, и каждая строка «только для
Claude» утекает в файл, который читают остальные инструменты. А бюджет токенов применяется к
*суммарному* объёму, поскольку импорты тоже загружаются при старте.

## ♻️ «У меня остался `SOUL.md` от ваших старых версий.»

**Тогда он мигрируется, а не выбрасывается.** Ранние версии проводили с вами интервью и писали
`SOUL.md`, загружаемый в каждую сессию через `@SOUL.md`. Теперь Claude Code делает это сам и
лучше — он сохраняет то, что узнаёт о вас, как **воспоминания, вызываемые по релевантности**, а
не загружаемые безусловно.

Интервью больше нет, а tune-up **конвертирует** то, что у вас есть: один файл памяти на факт,
правильно типизированный, показанный вам целиком — и только потом перемещает файл в точку
восстановления и убирает импорт `@SOUL.md`. Ничего не удаляется, пока замена не заработала, а
отмена возвращает и файл, и импорт.

> **«Воспоминания — по проектам. `@SOUL.md` загружался везде. Это даунгрейд.»**
> Подмечено — и учтено. Tune-up предлагает закрыть этот разрыв одной настройкой, чтобы
> мигрированные воспоминания действовали во всех проектах, — и он никогда не тронет ваш файл
> настроек, пока вы не скажете «да» именно на этот вопрос.

## ⚡ «Ладно. Что мне набрать?»

```bash
npx skills add paulovitin/claude-tuneup
```

Затем, в Claude Code:

```bash
claude-tuneup                    # запускает всё
claude-tuneup cleanup            # запустить группу по имени
claude-tuneup instructions       # аудит ваших правил + описаний
claude-tuneup 1-3                # запустить диапазон шагов
claude-tuneup 6,7                # запустить конкретные шаги
claude-tuneup claude.md soul.md  # комбинировать группы
claude-tuneup --dry-run          # сканирует + сообщает, что изменилось бы, ничего не трогая
claude-tuneup help               # список групп + триггеров
claude-tuneup restore            # отменить прошлый запуск (полностью или только конфиги/элементы)
claude-tuneup fix                # «X перестало работать»: найти виновный запуск и вернуть только это
```

**Первый раз? Начните с `--dry-run`** — он показывает всё, что *сделал бы*, и ничего не трогает.
(Он только читает: без изменений, без бэкапа. Но два диагностических вызова всё же выполняются —
`/doctor` и `/insights`, оба только для чтения и с часовым кэшем, — так что заложите ожидание
`/doctor`.)

| Группа | Шаги | Что делает |
| -------------------- | ------ | ------------- |
| 🧹 **`cleanup`**      | 1–8, 19 | Удаляет мусор + чинит целостность конфигов — навыки, плагины, хуки, MCP, проекты, каталоги состояния, корневые файлы, глобальный `.claude.json` и то, что на самом деле говорит `settings.json` — мёртвые пути, взаимно противоречащие правила доступа |
| 📝 **`instructions`** | 12–18   | Аудит каждой поверхности, грузящейся в сессию — правил, описаний навыков и агентов, slash-команд, output styles, компонентов плагинов: правила, которые должны быть суждением; инструкции, воюющие с рантаймом; одно правило в четырёх местах; описания, плохо маршрутизирующие; и процессы, которые вы повторяете, но так и не записали |
| 📄 **`claude.md`**    | 9       | Ваш глобальный `CLAUDE.md` + мост `AGENTS.md` *(для закоммиченного `CLAUDE.md` проекта запустите `/doctor` — он справится лучше)* |
| ♻️ **`soul.md`**      | 10      | Мигрирует устаревший `SOUL.md` в автопамять Claude и отправляет его на покой |
| 📊 **`summary`**      | 11      | Итоговый отчёт о том, что изменилось + как отменить *(всегда идёт последним)* |

Без аргумента запускается всё. Номера шагов исторические; порядок выполнения:
диагностика → вычитание → реорганизация → добавление.

**Обновление:** запустите снова `npx skills add paulovitin/claude-tuneup` — команда выполняется
в вашем шелле и стоит ноль токенов модели. Навык также напомнит (один раз, кэш на сутки), когда
выйдет более новая версия.

## 🧩 «Что именно выполняется на моей машине?»

**Чек-лист и несколько Node-скриптов — можете прочитать и то, и другое.** `SKILL.md`, которому
следует агент, плюс детерминированные помощники для механической части. Агент решает
(классифицировать, спросить, удалить/оставить); скрипты лишь собирают и применяют, и каждое
действие логируется, чтобы его можно было отменить.

```
skills/claude-tuneup/
├─ SKILL.md               # маршрутизация + UX-контракт + правила безопасности (лёгкий — грузится по триггеру)
├─ VERSION                # версия поставляемого навыка (питает напоминание об обновлении)
├─ references/            # плейбуки по группам, загружаются только когда группа запускается
│  ├─ cleanup.md          #   шаги 1–8, 19
│  ├─ instructions.md     #   шаги 12–18
│  ├─ harness-invariants.md  # что рантайм уже делает (список шага 13)
│  ├─ claude-md.md        #   шаг 9
│  └─ soul-md.md          #   шаг 10
└─ scripts/               # детерминированные, кросс-ОС (собрать и применить)
   ├─ scan.mjs            # обнаружение только для чтения → JSON (--section для одного среза)
   ├─ backup.mjs          # точка восстановления + снапшот + stash
   ├─ restore.mjs         # список / поиск / применение (полное, конфиги, элементы или один --only <путь>)
   ├─ ledger.mjs          # что вы решили в прошлом запуске, чтобы не спрашивать снова (никогда содержимое файлов)
   ├─ doctor.mjs          # запускает встроенный /doctor headless, только отчёт (кэш 1ч)
   ├─ insights.mjs        # запускает /insights headless (кэш 1ч; --no-cache)
   ├─ audit-instructions.mjs  # сигналы инструкций + резидентные описания → JSON
   ├─ consolidate.mjs     # переносит навык в ~/.agents/skills + ссылка обратно (junction на Windows)
   ├─ validate-json.mjs   # проверка корректности JSON после каждой правки конфига
   └─ version-check.mjs   # дешёвое по токенам напоминание об обновлении (кэш 24ч, молчит офлайн)
skills.sh.json             # манифест реестра
```

> **«Он работает на Windows по-настоящему или "работает на Windows"?»**
> Помощники — чистый Node, без зависимостей и **без требования `python3`**, поэтому работают
> одинаково на macOS, Windows и Linux через `node`, который Claude Code уже поставляет. На
> Windows консолидация навыков использует junction там, где симлинкам нужны права
> администратора. Всё критичное для безопасности покрыто автоматическими тестами (юнит +
> сквозные циклы backup→restore), выполняемыми в CI на всех трёх системах.
