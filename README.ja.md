# claude-tuneup

### Claude用に書いた指示ルール、古いモデルのままで無駄なトークンコストになっていませんか？

AIエージェントが**毎セッション**読み込まれる指示ルールを監査し、ディスクの不要ファイルもクリーンアップします。<br/>
変更はすべてボタン選択。各ボタンに「これ何をするの？」説明付き。いつでもロールバック可能。

> [!IMPORTANT]
> **ご存知ですか？** AnthropicはClaude 5世代モデルにおいて、Claude Code自身のシステムプロンプトの**80%以上**を削減しました。過去のモデル用に書かれた `CLAUDE.md` や `SOUL.md` の古い指示ルールは、毎セッションで無駄なトークンを消費しています。 `claude-tuneup` はAnthropicの公式ガイドラインに基づいてコンテキストを最適化します。

Claude Code を何ヶ月も使うと、ディスクに痕跡が溜まります。しかし本当に高くつく痕跡は指示ルールの中にあります。古いモデルを補うために書いたルール、4つのファイルにコピーされた同じ指示、うまくルーティングしないスキルの description、関係あるなしにかかわらず毎セッション課金される `SOUL.md`。これらすべてが、あなたが一文字打つ前に読み込まれています。

そのどれかに触ろうとするツールに、あなたは異議があるはずです。**結構。** このツールはまさにあなたのような人のために作られました — ですから、一つずつ聞かせてください。もう納得済み？ インストールコマンドは[この下](#-わかった何を打てばいい)にあります。まだ疑っている？ なお良し。読み進めてください。

## 🧐 「*私が*書いたルールを書き換えたいだって？」

**いいえ — *提案*したいだけで、ペンを握るのはあなただけです。** `instructions` グループ（ステップ12–18）が勝手にルールを編集することはありません。元の行、提案する書き換え、その理由を提示し、あなたがボタンを押すまで何も変えません:

```text
> claude-tuneup

📝 ステップ12: 判断に任せるべきルール

   ~/.claude/CLAUDE.md:14
   「デフォルトではコメントを書かない。複数段落のdocstringは絶対に書かない。」

   古いモデル向けに書かれたもの。現行モデルは周囲のコードを読み取ります。
   提案: 「周囲のコードに馴染むコードを書く: コメントの密度、命名、
         イディオムを周囲に合わせる。」

   [ 書き換える ]   [ そのまま維持 ]   [ 削除する ]   [ これ何をするの？ ]
```

このトランスクリプトでは伝わらない3つのこと:

- **安全に関わる絶対ルールは不可侵です。**「main に絶対 push しない」「シークレットを絶対コミットしない」のようなルールは**一字一句そのまま**維持されます — 決して和らげず、決して「改善」しません。
- **フラグ付きルールを維持するのは常に正当な回答です。** ツールはフラグを立てるだけ。判断するのはあなた。
- **正体不明なものを判断させられることはありません。** すべての質問に「これ何をするの？」オプションがあり、決断の**前に**対象を調査して説明します。

## 📐 「何を根拠に書き換える — あなたの好みか？」

**意見はゼロです。** `instructions` グループの各チェックは、Anthropic の
[**The new rules of context engineering for Claude 5 generation models**](https://claude.com/blog/the-new-rules-of-context-engineering-for-claude-5-generation-models)
の一つのルールを実装しています:

| ルール | チェック |
| --- | --- |
| 硬直したルールより判断を優先する | **ステップ12** — 古いモデルを補うために書かれたルールを書き換える。安全の絶対ルールは一字一句維持 |
| ハーネスと戦わない | **ステップ13** — ランタイムが既にやっていることと矛盾する指示をフラグする |
| 一度だけ言う | **ステップ14** — `CLAUDE.md`、エージェント本体、エージェントとスキルの description に同じ指示が重複していないか |
| 例文よりインターフェース | **ステップ15** — 例文のフレーズではなく能力でルーティングする `description` フィールド |
| 段階的開示 | **ステップ16** — 常時ロードすべきものと、遅延ロードのスキルにすべきものの仕分け |
| 記憶は自動メモリに任せる | **ステップ10** — `SOUL.md` は Claude Code 自身のメモリへ引退 |

このツールは「何が削除できるか？」とは別の質問をします — **「これはまだ役に立っているか？」**と。
そしてスキル自身にも同じルールを課しています: 実行中のグループのプレイブックだけがコンテキストに入る — あなたの `CLAUDE.md` に求めるのと同じトークン規律です。

## 🔁 「では実行のたびに同じことを聞かれるのか？」

**そうならざるを得なかった — 実行間で何も残らなかったからです。** 2回目のチューンアップは1回目の記憶なしにやってきました: 同じ指摘、同じ拒否、同じ回答。今はあなたの判断が記録され、再実行は蒸し返しではなく1行から始まります:

```text
> claude-tuneup

前回のチューンアップ（2026-06-14）から常駐コンテキストが約380トークン増えています。
前回「残す」と言われた3件 — スキップしました。（`--all` で再確認できます。）
```

- **書き直したルールは再び出てきます。** キーはパスではなく*本文*をハッシュします。だから書き換えられたルールは再び提案されます — 正しく、です: あなたはその文面を承認していません。段落を整形し直しただけなら何も起きません。空白は先に正規化されるからです。
- **黙って消えるものはありません。** 拒否はその1行に畳まれるだけで、無にはなりません。
- **覚えるのはあなたの判断であって、あなたの文章ではありません。** パス、ハッシュ、判定 — 指示ファイルの中身は決して保存しません。バックアップの隣に置かれるので、ある実行を取り消しても他のすべての実行での判断は消えません。

## 🩺 「Claude Code には `/doctor` があるだろう。なぜ君が存在する？」

**`/doctor` が先に走るからです — このツールがそれを譲りません。** インベントリ作成は `/doctor` の方が上手です: 全プロジェクトにわたるコンポーネントごとの実際の使用状況や常駐トークンコストが見える。外部スキルには測れないものです。だから claude-tuneup はあなたの代わりに `/doctor` を実行し、そのレポートを土台に、`/doctor` が触れない部分に自分の労力を注ぎます: **グローバル**の `CLAUDE.md`、エージェントとスキルの description、レガシーな `SOUL.md`、そしてディスク。代替ではなく補完です。

> **「スキルがヘッドレスで `/doctor` を走らせるとき、*そっち*が何かを変えない保証は？」**
> 呼び出しには常にレポート専用の指示が付き、スキルが組み立てるすべてのコマンドにそれが含まれることをテストが検証しています — ヘッドレス実行には確認プロンプトがないため、指示がセーフガードであり、テストはセーフガードのセーフガードです。

⏱️ 正直な見積もり: フル実行は冒頭の `/doctor` パスで約**6分**待ち、結果検証にさらに6分使う前に許可を求めます。

## 🗂️ 「チャット履歴に触るのか？」

**あなたが依頼し、フォルダごとに確認し、警告を了承しない限り触りません — 一括では決して。**
会話トランスクリプトとセッション状態（`projects/`、`todos/`、`shell-snapshots/`、`file-history/`、`history.jsonl`）はマシン上で最も取り返しのつかないデータであり、**決して**一括削除されません。デフォルトは*維持*。せいぜい期間指定の剪定を提案するだけです — 「6ヶ月より古いトランスクリプト: 142セッション、1.2G」— フォルダごとの明示的な確認付きで、恒久的な削除であり `--resume` と `/insights` が壊れることを先に警告します。

## ↩️ 「クリックを後悔する日が来たら？」

```bash
claude-tuneup restore    # 復元ポイントを選択 → 全部、設定のみ、またはアイテムのみ
```

**すべての実行が復元ポイントです。** 設定はスナップショットされ、削除されたアイテムは `rm` されるのではなく `~/.claude-tuneup/backups/<run-id>/` へ*移動*されます。スキルディレクトリの**外**に保管されるため、アップデートや再インストールで取り消し履歴が消えることはありません（`$CLAUDE_TUNEUP_STATE` で上書き可能）。`.claude.json` はトークンを含み得るため、スナップショットは所有者のみ読める権限です。

実行は引くだけでなく*足し*もします。取り消しは今や両方を戻します: 実行中にあなたのために書かれたスキルは記録され、完全復元で取り除かれます — 削除ではなく `undone-creations/` へ*移動*します。あなたがそれを編集済みかもしれないからです。

> **「復元そのものが何かを壊す可能性は？」**
> 復元もパラノイアです。ロールバック前に*現在の*設定を `pre-restore-…` フォルダにスナップショットし（つまり取り消しすら取り消せる）、削除された場所を再び使っている新しいアイテムを上書きすることはありません: 衝突は `<パス>.restored-<ts>` に着地し、報告されます。

## 🔎 「3日後に、別のセッションで壊れたら？」

**その場合には専用の入口があります。** `restore` は「どの実行を取り消すか」を知っている前提です。3日経てば分かりません — 手元にあるのは実行IDではなく症状です:

```text
> claude-tuneup fix

   「コミットについて書いていたルールが消えた」

   2つの復元ポイントが該当 — 順位付けであって、断定ではありません:

   ● 2026-06-14 14:02   CLAUDE.md:14 「push前にsquash」   (削除)
     2026-06-02 09:31   actions.log — スキル「git-helper」を統合

   [ それだけ戻す ]   [ 実行全体を見る ]   [ どちらでもない ]
```

- **どの復元ポイントにも元からあったものを読みます** — 削除されたパス、アクションログ、そしてスナップショットされた `CLAUDE.md`/`AGENTS.md`/`SOUL.md`。証拠は最初からそこにありました。読み返す手段がなかっただけです。
- **リグレッションは両方向から来ます。** 分かりやすい原因は削除ですが、実行が*作成*したスキルが既存のものを覆い隠し、何も消さずにルーティングを変えることがあります。この2つは逆の対処が必要なので、方向は記録から読み取り、パスから推測しません。
- **戻るのは1件で、実行全体ではありません** — そのチューンアップの残りは適用されたままです。復旧自体も記録されるので、次の実行が「たった今壊れた当のもの」を再提案することはありません。
- **あなたの秘密は検索対象外です。** `.claude.json` と `settings*.json` は検索が決して読みません: トークンを含み得るうえ、検索結果はあなたに印字して返すテキストだからです。

## 🧯 「まだ聞き忘れていることは？」

あなたが心配しなくて済むよう、先回りして心配しておいた故障モード:

- **ファイル形式の変更で大量アンインストールに誘導されることはありません。** ディスクにプラグインの実体があるのに `installed_plugins.json` が空にパースされた場合、スキルは「リストにない」を「アンインストール済み」として扱うことを拒否します。
- **無意味な容量回収は売りつけません。** 自己再生するアーティファクト（venv、キャッシュ、ランタイム、`statsig`）は検出され、来週には再生成されるものを削除する代わりに、本当の解決策（所有プラグインの無効化）を提示します。
- **推測ではなく発見します。** アイテムは特徴 — サイズ、経過期間、壊れたリンク、トランスポート種別 — で分類され、ハードコードされた名前では分類されません。
- **`/insights` のデータはあなたのものです。** 提案のためにライブで読むだけで、スキル内や共有される場所へコピーされることはありません。MCP 設定内のインライン認証情報は環境変数の**名前**だけでフラグされ、値は決して印字されません。

## 🤝 「うちは `AGENTS.md` で標準化している。ケンカにならないか？」

**逆です — きれいな橋を架けます。** Claude Code は `AGENTS.md` を自動読み込みしないため、クロスツール規約（Codex、Cursor、Gemini CLI…）のリポジトリはたいてい、**静かに乖離していく** `CLAUDE.md` のコピーを抱えることになります。tune-up はその乖離を検出して統合を提案します: 共有すべき事実は `AGENTS.md` に一度だけ置き、`CLAUDE.md` は3行のシムになります —

```markdown
@AGENTS.md

# Claude固有
- (Claude Codeだけが見るべき差分)
```

オプトインの質問一つだけ。Claude のみのユーザーには表示されません。ここではインポートがシンボリックリンクに勝ります: シンボリックリンクは `CLAUDE.md` を `AGENTS.md` *そのもの*にしてしまうので、Claude 専用の行がすべて他のツールが読むファイルに漏れます。そしてトークン予算は*合算*で適用されます。インポートも起動時に読み込まれるからです。

## ♻️ 「昔のバージョンの `SOUL.md` がまだ残っているんだが。」

**なら移行します。捨てません。** 以前のバージョンはあなたにインタビューして `SOUL.md` を書き、`@SOUL.md` 経由で毎セッション読み込んでいました。今の Claude Code はこれを自分で、より上手にやります — あなたについて学んだことを、無条件に読み込むのではなく**関連するときに想起されるメモリ**として保存します。

だからインタビューは廃止され、tune-up は手元のものを**変換**します: 事実ごとに1つのメモリファイル、正しく型付けし、全文をあなたに提示 — その後で初めてファイルを復元ポイントへ移動し、`@SOUL.md` インポートを除去します。代替が稼働する前に削除されるものは何もなく、取り消せばファイルもインポートも戻ります。

> **「メモリはプロジェクト単位だろう。`@SOUL.md` はどこでも読み込まれた。ダウングレードじゃないか。」**
> 鋭い — そして対策済みです。tune-up は、移行したメモリが全プロジェクトで効くように設定一つでそのギャップを埋めることを提案します。そして、まさにその質問にあなたが「はい」と言わない限り、settings ファイルには決して触れません。

## ⚡ 「わかった。何を打てばいい？」

```bash
npx skills add paulovitin/claude-tuneup
```

その後、Claude Code 内で:

```bash
claude-tuneup                    # 全部実行
claude-tuneup cleanup            # グループ名で実行
claude-tuneup instructions       # ルール + description を監査
claude-tuneup 1-3                # ステップ範囲を実行
claude-tuneup 6,7                # 特定のステップを実行
claude-tuneup claude.md soul.md  # グループを組み合わせ
claude-tuneup --dry-run          # スキャン + 変更予定を報告、何も触らない
claude-tuneup help               # グループ + トリガー一覧
claude-tuneup restore            # 過去の実行を取り消し（全部、または設定/アイテムのみ）
claude-tuneup fix                # 「Xが動かなくなった」: 原因の実行を特定し、それだけを戻す
```

**初めてなら `--dry-run` から** — *やるであろう*ことをすべて表示し、何も触りません。
（読み取りのみ: 変更なし、バックアップなし。ただし2つの診断呼び出し — `/doctor` と `/insights`、どちらも読み取り専用で1時間キャッシュ — は行うので、`/doctor` の待ち時間は見込んでください。）

| グループ | ステップ | 何をするか |
| -------------------- | ------ | ------------- |
| 🧹 **`cleanup`**      | 1–8, 19 | 不要物の除去 + 設定の整合性修復 — スキル、プラグイン、フック、MCP、プロジェクト、状態ディレクトリ、ルートファイル、グローバル `.claude.json`、そして `settings.json` が実際に何を言っているか — 死んだパス、互いに矛盾する権限ルール |
| 📝 **`instructions`** | 12–18   | 毎セッション読み込まれる全サーフェスを監査 — ルール、スキルとエージェントの description、スラッシュコマンド、output styles、プラグイン同梱コンポーネント: 判断に任せるべきルール、ランタイムと戦う指示、4箇所にある同じルール、うまくルーティングしない description、繰り返しているのに書き留めていないワークフロー |
| 📄 **`claude.md`**    | 9       | グローバル `CLAUDE.md` + `AGENTS.md` ブリッジ *(プロジェクトにコミットされた `CLAUDE.md` は `/doctor` へ — その方が得意です)* |
| ♻️ **`soul.md`**      | 10      | レガシー `SOUL.md` を Claude の自動メモリへ移行し、引退させる |
| 📊 **`summary`**      | 11      | 変更内容 + 取り消し方法の最終レポート *(常に最後に実行)* |

引数なしで全部実行。ステップ番号は歴史的なもので、実行順は「診断 → 削減 → 再編成 → 追加」です。

**更新:** `npx skills add paulovitin/claude-tuneup` を再実行 — シェル内で走るのでモデルトークンはゼロ。新しいリリースがあるとスキルが（1回、1日キャッシュで）お知らせもします。

## 🧩 「私のマシンで実際に何が動いているんだ？」

**チェックリストといくつかの Node スクリプト — どちらも読めます。** エージェントが従う `SKILL.md` と、機械的な部分を担う決定的なヘルパー群。エージェントが判断し（分類、質問、削除/維持）、スクリプトは収集と適用だけを行い、すべてのアクションは取り消せるようログに残ります。

```
skills/claude-tuneup/
├─ SKILL.md               # ルーティング + UX契約 + 安全ルール（軽量 — トリガー時に読み込み）
├─ VERSION                # 配布中のスキルバージョン（更新通知を駆動）
├─ references/            # グループ別プレイブック。そのグループの実行時のみ読み込み
│  ├─ cleanup.md          #   ステップ1–8, 19
│  ├─ instructions.md     #   ステップ12–18
│  ├─ harness-invariants.md  # ランタイムが既にやっていること（ステップ13のリスト）
│  ├─ claude-md.md        #   ステップ9
│  └─ soul-md.md          #   ステップ10
└─ scripts/               # 決定的、クロスOS（収集 & 適用）
   ├─ scan.mjs            # 読み取り専用の探索 → JSON（--section で一区画のみ）
   ├─ backup.mjs          # 復元ポイント + スナップショット + 退避
   ├─ restore.mjs         # 一覧 / 検索 / 適用（全部、configs、items、または --only <パス> で1件だけ）
   ├─ ledger.mjs          # 前回あなたが下した判断。再実行で聞き直さないため（ファイルの中身は決して保存しない）
   ├─ doctor.mjs          # 内蔵 /doctor をヘッドレス実行、レポートのみ（1時間キャッシュ）
   ├─ insights.mjs        # /insights をヘッドレス実行（1時間キャッシュ; --no-cache）
   ├─ audit-instructions.mjs  # 指示のシグナル + 常駐 description → JSON
   ├─ consolidate.mjs     # スキルを ~/.agents/skills へ移動 + リンクで戻す（Windowsはjunction）
   ├─ validate-json.mjs   # 設定編集のたびに JSON 妥当性チェック
   └─ version-check.mjs   # トークン負荷の軽い更新通知（24時間キャッシュ、オフライン時は沈黙）
skills.sh.json             # レジストリマニフェスト
```

> **「Windows で本当に動くのか、それとも『Windows でも動きます』程度か？」**
> ヘルパーは純粋な Node — 依存関係なし、**`python3` 不要** — なので、Claude Code が同梱する `node` を通じて macOS、Windows、Linux で同一に動作します。Windows では、シンボリックリンクに管理者権限が必要な場面でスキル統合がジャンクションにフォールバックします。安全に関わるすべての部分は、3つのOSのCIで走る自動テストスイート（ユニット + エンドツーエンドの backup→restore 往復）でカバーされています。
